The first three runs ended `ENVIRONMENT_ERROR` at the hypotheses stage. The fourth demonstrates real PR ingest, Dell CUDA context ranking, live Nemotron test generation and Docker execution of the generated file, but **not a confirmed regression or successful autonomous end-to-end review**. The app ledger after the fourth run showed nine historical provider calls, 5,068 input tokens, 16,719 output tokens and **$0.004320 estimated lifetime use**. These are AegisPR's accounting figures, not a provider invoice or guaranteed remaining credit. The fourth run's analysis and sandbox stages took 67,380 ms and 56,109 ms respectively; these are one-run observations, not a benchmark.

The stale backend image was replaced without changing its `.env`, GPU worker, frontend, or other containers. Before the replacement, both SQLite databases were backed up in the private data volume and the old image was tagged `aegispr-backend:pre-20261024-model-review`. Afterward `/health` reported Nebius configured, sandbox enabled and GPU accelerator `cuda`; the failed run and budget ledger were still readable.

Source change `420ae11` made the single planning response compact: one hypothesis/test file covering both old-code and new-code input angles, at most eight labeled examples, with an 8,192-token first-response allowance. The third live call proved that this change alone was **insufficient**. Nebius's [public model catalog](https://tokenfactory.nebius.com/api/public/models_info) does not label Nemotron 3.5 Lightning with `JSON mode`, while the previous gateway forced `response_format=json_object`. The [Token Factory JSON guide](https://docs.tokenfactory.nebius.com/ai-models-inference/json) says support varies by model. Its [completion API](https://docs.tokenfactory.nebius.com/api-reference/inference/create-chat-completion) offers a `reasoning_effort=none` control. Source change `8963578` therefore uses prompt-requested JSON without forced JSON mode and disables reasoning for NVIDIA Nemotron requests. The fourth live run validates that configuration for this one planning task; it does not establish general model quality.

The fourth run's generated Python file was an assertionless top-level example rather than a collected pytest function. Its output was visible in logs, but the runner's pytest exit code 5 made both branches fail. Commits `ddda72e` (red test) and `47ff0d2` (fix) make assertionless Python output examples run as scripts while retaining pytest for conventional test functions. The full local backend suite passed **233 tests with 88.76% coverage**, and [all six CI jobs passed](https://github.com/Hari-Aditya-003/AegisPR/actions/runs/40090641152). The fixed backend alone was deployed to Dell after tagging its predecessor `aegispr-backend:pre-20261024-output-script`; health checks passed. No further provider call was made after that deployment.

### Zero-token replay of the saved generated example

An operator replayed the **already-generated** test from run `4751e57c-dfdf-408a-87cc-cbae27328105` against the exact base and PR commits in the fixed Docker sandbox. The example called `apply_coupon(5, 8)` and printed a labeled JSON observation. All three base executions passed with exit 0 and value `0`; all three PR executions passed with exit 0 and value `-3`. The output difference was stable across these three attempts on each commit. Provider call count stayed at nine before and after replay.

This is manually initiated, offline Docker replay of a live-model-generated example. It proves a stable **behavior change in the controlled fixture**, not an autonomous `REGRESSION_FOUND` product verdict, a human-confirmed unintended change, a verified repair, or a real-world benchmark. The original live run remains `INCONCLUSIVE`. A new paid end-to-end attempt would require separate owner approval; do not silently retry it or quote the replay as a successful live review.
