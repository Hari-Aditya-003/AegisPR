# Research-driven verification workflow (updated October 25, 2026)

This page separates **implemented and locally tested code** from **unverified live model behavior**. The design draws on [Testora's behavior-and-intent approach](https://arxiv.org/abs/2503.18597) and [ACH's mutation-guided test-strength idea](https://arxiv.org/abs/2501.12862). AegisPR does not include code copied from either project, and their reported accuracy, time, or cost are not AegisPR measurements.

## Implemented, covered by local tests

1. The planner requests assertionless usage examples. Each generated test is marked `output` or `assertion`. Output tests emit labeled JSON `AEGISPR_OUTPUT=` values; the runner captures Python pytest output or runs a top-level Python output example as a script when pytest would collect no tests. It compares canonical JSON from the base and PR commits. Runner chatter and JSON object key order are ignored. Missing, malformed, mismatched-count, failing or timed-out observations are inconclusive rather than regressions.
2. The single bounded planning request asks for inputs from two perspectives: old-code weaknesses and new-code weaknesses, with up to eight normal/edge inputs in one test file. The prompt now explicitly requires one hypothesis object, one test object and imports inside its `test_code` after an October 24 live response incorrectly emitted eight then four separate test objects. The validator still caps accepted plans at two of each for compatibility. The model's actual input diversity and accuracy **have not been measured**. This scope keeps sandbox work and the user's $25 credits bounded; it is not equivalent to a 20-call model fan-out.
3. A changed output is rerun twice on **each** commit in fresh checkouts. Only a stable match with the first observations remains `BEHAVIOR_CHANGE`; variation becomes `INCONCLUSIVE`. These reruns add Docker work and are not a measured speed improvement.
4. For one stable behavior change per run, the optional Nemotron intent review receives bounded PR title, description, up to ten commit messages, hypothesis and before/after logs. Three independent requests ask whether the difference is intentional, pre-existing, harmful or needs human review. Majority voting yields `intended`, `unintended` or `unclear`; invalid/tied votes become `unclear`. This is **advisory**. Even three `unintended` votes do not create a confirmed regression or unlock automatic repair. A human should inspect the evidence.
5. A generated test failing on base can be refined up to two times using its bounded error log. Each revision is executed on a fresh base checkout **before** the PR execution. The original and revised base receipts are retained. If the model or budget is unavailable, the loop stops safely. No automatic SDK retry is enabled.
6. A Python changed-line operator (`>`, `>=`, `<`, `<=`, `==`, `!=`) can be flipped in an isolated head checkout. A generated test then runs against that mutant. `mutation_catch_rate` is reported only for valid executed mutants, with numerator and denominator visible. This is one deterministic mutant per eligible generated test, not a comprehensive mutation campaign. JavaScript/TypeScript mutation is not yet supported.
7. The report UI exposes rerun counts, refinement receipts, advisory intent votes and the bounded mutation score without claiming a behavior change is a proven bug. Both run and inference ledgers use SQLite WAL for concurrent reads.
8. For simple root npm lockfiles or pinned Python requirements, Docker copies only dependency manifests and installs before copying source. The dependency layer can therefore be reused when generated tests or source change. Workspaces, local dependencies, npm configuration and nested/unpinned Python requirements keep the full-source install path. This is a cache-layout implementation, **not a measured speedup**; no local Docker daemon was available for before/after timings.
9. Impact graph edges now require a resolvable Python or JavaScript/TypeScript local import. A changed filename appearing only in a comment or string no longer adds an edge. This is a conservative direct-import graph, not yet a full call graph or a guarantee that all relevant files are in the 100-document context window.
10. A malformed or schema-invalid verification **plan** receives at most one bounded correction request. It consumes a normal admission-ledger slot and can be blocked before reaching the provider. HTTP 402, transport errors and output truncation are not retried. Other model stages still have no JSON-correction loop.
11. A separate [12-case synthetic evaluation dataset](../evals/seeded-prs/README.md) covers eight seeded unintended changes, three explicitly intended changes and one no-change refactor across Python and JavaScript. Tests execute every committed base/head fixture and compare its observations to hand-authored ground truth. The CLI can materialize local two-commit Git repositories. Neither that fixture validation nor its labels measure AegisPR detection accuracy.

The existing durable admission ledger still enforces **$20 total estimated**, **$0.25 estimated per run** and **five provider attempts per run**, with zero SDK automatic retries. One plan correction, two refinements and three intent votes would exceed five attempts; optional intent review is skipped when three calls are not available. A model output error or failed provider call does not silently override this cap. An October 23 model-only connectivity check succeeded. Of five [October 24 controlled-PR runs](live-pr-attempt-2026-10-24.md), the fourth generated and executed one model-written example but ended `INCONCLUSIVE`; the fifth stopped at plan validation after one correction. The [October 25 continuation](live-pr-continuation-2026-10-25.md) generated a four-case example in one paid call. A file-collision fix then allowed the full app to reuse that saved response **without new inference**, execute and confirm a stable `BEHAVIOR_CHANGE`; its overall result remained `INCONCLUSIVE` because intent was unverified. This is not a confirmed regression or validation of repair generation. Do not repeat old HTTP 402 probes or spend credits without fresh owner approval and a bounded plan.

## Pending evidence or implementation

| Research suggestion | Honest current state |
| --- | --- |
| Real-PR benchmark of 10–20 merged PRs, bugs, false alarms, duration and provider cost | **Not measured.** A separate 12-case synthetic dataset is available for deterministic fixture checks. A model-only completion and controlled-PR calls occurred, but none yielded a completed autonomous verdict. Hand labels and the controlled PR cannot supply independent real-PR accuracy or cost numbers. Select real PRs and record exact commits, human labels, timestamps and provider receipts before reporting results. |
| Stronger tests after an uncaught mutant | Mutation catch/miss is recorded, but automatic model strengthening from an uncaught mutant is not yet wired. It needs another budgeted call and rerun. |
| Faster sandbox via base/head image reuse, cached dependency layer and parallel execution | A conservative Docker dependency cache layer is implemented for eligible projects. Base/head image reuse and parallel execution are not yet implemented or benchmarked; tests still build per generated test and rerun. Do not claim a speedup over Testora. |
| Import-graph context, batched Git reads, function-level ranking and measured code embeddings | Direct-import impact edges are implemented for Python and relative JS/TS imports. Import-prioritized context selection, batched Git reads, function-level ranking and measured embeddings remain open. One configured model remains; a verified Lightning-versus-larger-model policy has not been tested live. |
| GitHub PR comment / Action | No opt-in posting feature yet; no comments were sent to third-party repositories. |
| Tavily runtime search | Not integrated. Do not select “yes” on a submission form until an actual runtime Tavily API call is implemented and verified. |

## Local validation receipt

On October 23, `make test` passed after the dataset and plan-correction edits: **206 backend tests at 90.05% coverage**, **33 frontend unit tests**, **7 browser E2E tests**, **16 public-website tests**, plus the configured GPU-worker, demo-repository and recorder checks. The standalone dataset validator verified all 12 committed fixture pairs. All five CI jobs previously passed for commit `f78c8dd`, including the full transitive Python audit and real controlled Docker acceptance; the newer edits must receive their own CI result before being described as CI-verified. These are implementation checks, not a live PR benchmark, model-quality rating, security certification or proof that every generated example executes on a public repository. Use [submission readiness](submission-readiness.md) for the outstanding judging gates.
